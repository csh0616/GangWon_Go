## 5. 심사위원 첫 접속 동선 점검 (PRD 11.5절, 3주차)

> **심사 방식 확정: 심사위원이 배포 URL에 직접 접속한다** — 무대 시연도, 사전 녹화 영상도 아니다.
> 따라서 이 섹션의 목적은 "발표 대사를 고정하는 것"이 아니라, **안내해주는 사람 없이 처음 들어온
> 사람이 핵심 기능 전부에 스스로 도달할 수 있는지** 확인하는 것이다.
>
> **점검 방법**: 팀원 중 이 프로젝트를 만들지 않은 사람(또는 화면을 처음 보는 지인)에게 URL만 주고
> 아무 설명 없이 써보게 한다. 아래 7단계 중 **막히거나 되묻는 지점이 곧 결함**이다 — 그 자리에서
> 6장 결함 로그에 적는다. 개발자가 직접 클릭해보는 건 이 점검이 되지 않는다(어디를 눌러야 하는지
> 이미 알고 있기 때문).

| 단계 | 확인 항목 | 막히면 안 되는 이유 |
|---|---|---|
| 1 | 랜딩 진입 → 로그인 요구 없이 코스 생성 폼이 바로 보임 | 가입 장벽에서 이탈하면 그 뒤 전부 못 봄 |
| 2 | 시군·날짜·인원·동행 입력 → 자유 텍스트는 **비워둔 채로도** 생성됨 → 3초 이내 결과 | 자유 텍스트를 필수로 오인하면 여기서 멈춤 (T-001) |
| 3 | 코스 결과에서 지도·스탑 순서·이동시간 확인, 언어 전환(영/중) 동작 | 다국어가 Must-have (PRD 2.1절) |
| 4 | "코스 저장" → Google 로그인 → 3초 이내 "저장됨" | 로그인 실패 시 코스가 사라지면 안 됨 (T-009) |
| 5 | **"지금 코스 점검하기"** → 3초 이내 제안 모달 → Yes → 해당 스탑만 교체 | **날씨가 맑으면 자동 스캔은 아무것도 안 만든다.** 이 진입점이 없거나 눈에 안 띄면 실시간 매니징이 심사에서 통째로 안 보임 (T-003) |
| 6 | 마이페이지에서 방금 만든 코스가 보이고, 다시 열리고, 삭제됨 | 재방문 경로가 끊기면 저장 기능이 무의미 (T-015) |
| 7 | 여행 케어 안내 → 로그인 여부 무관하게 열림, SOS → `tel:119` | 안전 기능이라 가입 장벽이 없어야 함 (T-005) |

> **문구는 대사가 아니라 템플릿으로 검수한다**: 심사위원이 어떤 시군·날짜·취향을 넣을지 통제할 수
> 없으므로, 5단계의 판정 기준은 "정해진 장소명이 나오는가"가 아니라 "질문형 템플릿이 성립하고
> 장소명이 실데이터로 정상 치환되는가"다 (T-003, PRD 11.5절).
>
> **심사 기간 내내 살아 있어야 한다**: 접속 시점을 우리가 고를 수 없으므로, 기상청·카카오맵 호출이
> 실패해도 화면이 비면 안 된다. 네트워크 차단 상태에서 폴백이 실제로 뜨는지 함께 검증한다 (B-001).
